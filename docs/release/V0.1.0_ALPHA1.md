# Polynovea CMS v0.1.0-alpha.1

This is the first public OSS prerelease of Polynovea CMS: a workspace-scoped headless CMS and governed content-operations platform for teams that want structured content, editorial control and programmable delivery without surrendering their data model.

## Included

- Visual structured-content models and typed entries
- Editorial workflow, collaboration, localization, scheduling and releases
- Preview, routing, redirects, navigation and web-quality controls
- Media operations through the supplied R2/S3-compatible adapter
- Scoped REST API, OpenAPI contract, TypeScript SDK and CLI
- Persistent delivery jobs for publishing, webhooks, indexing, images, health and analytics
- Search, analytics freshness, content health and remediation queues
- Environment, connection, backup/restore planning and system diagnostics
- Governed agent, MCP and extension foundations
- Idempotent first-owner bootstrap and starter-content commands

## Supported profile

- Node.js 22+
- A managed or independently operated Supabase-compatible backend with PostgreSQL 15+, PostgREST and GoTrue Auth
- A persistent external process for `npm run worker:delivery` when durable job features are enabled
- Optional Cloudflare R2 or compatible S3 media storage

Start with the [README](../../README.md) and [development quickstart](../getting-started/LOCAL_QUICKSTART.md). The [acceptance record](OSS_ACCEPTANCE_2026-09-21.md) documents the clean-install and live capability evidence behind this prerelease.

## Known limitations

- Supabase-compatible Auth and data APIs are required; generic PostgreSQL-only deployments are not yet supported.
- R2 is the first-class tested media adapter; other S3-compatible providers may need configuration or adapter work.
- The application and worker are deployed separately; the worker cannot run as a Vercel request function.
- This alpha has not yet accumulated independent production-adopter or upgrade-history evidence.
- Public SDK/CLI package publication is separate from this source release.

## Security

Do not expose the service-role key, database URL, encryption key or integration credentials to browser code. Follow [SECURITY.md](../../SECURITY.md) and report vulnerabilities privately through GitHub Security Advisories.
